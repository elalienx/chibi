Why a shorter codebase matters

  • 🐞 Fewer bugs. Code size is one of the strongest predictors of defects: studies consistently find that the number of faults grows with lines of code (El Emam et al., 2001; McConnell, Code Complete).
  • 🤖 Lower AI cost. AI skills help agents find code in big codebases, but they still have to read it. Fewer lines mean fewer tokens, cheaper requests and more accurate answers (Liu et al., 2023).
  • 🛠️ Cheaper maintenance. Maintenance makes up 60–80% of a software system's lifetime cost, and it scales with the amount of code to maintain (Glass, Facts and Fallacies of Software Engineering).
  • 🔍 Better code reviews. Reviewers find defects effectively up to about 200–400 lines at a time; smaller changes get more thorough reviews (SmartBear / Cisco code review study).
  • 🚀 Faster onboarding. Less code lowers cognitive load, so new team members can become productive sooner (Sweller, 1988).
